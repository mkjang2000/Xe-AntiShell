# 관리형 에이전트 원격 제거

## 범위와 완료 조건

제거 권한을 부여받은 사용자는 에이전트 상세 화면이나 일괄 제거 미리보기에서 대상의 현재 등록에 RPM 제거를 요청하고 진행 상태를 확인한다. 제거를 마친 작업자가 RPM 데이터베이스에서 대상 패키지 부재를 확인해 보고하면 센트럴이 같은 등록의 인증서를 폐기한다. 호스트의 이력, 운영 증거와 데이터 디렉터리는 보존하며 제품 패키지 제거와 기존의 수동 승인·등록 해지는 각각 별도 작업이다.

## 권한과 실행 경로

- 관리형 RPM은 해당 계약을 지원하는 센트럴의 요청을 기본으로 확인한다. 운영자가 현장에서 제거를 차단하려면 호스트 설정이나 구성 관리에 명시한다. 센트럴의 보안 정책과 원격 운영 설정은 호스트 설정을 변경할 수 없다.
- 콘솔은 세션, CSRF, 사이트별 제거 권한을 검증한다. 요청을 발행할 때와 실행을 허용할 때 같은 등록과 사이트인지 확인한다. 센트럴의 지정 정책이나 에이전트의 현재 정책이 일반 제거를 금지하면 제거가 진행되지 않는다.
- 센트럴은 5분간 유효한 서명 요청을 만들고, 현재 등록의 mTLS 연결로 전달한다. 에이전트는 전용 서명을 확인한 뒤 기존 로컬 챌린지를 준비한다. 센트럴은 같은 요청과 챌린지에 묶인 일회용 제거 승인을 발행한다. 감사 기록은 요청과 로컬 작업을 연결한다.
- 독립 systemd 작업자가 업데이트와 같은 잠금을 사용하고, 로컬 제거 게이트 및 제거 감사 ACK와 센트럴 시작 ACK를 확인한 후 정상 RPM 제거 절차를 실행한다. 이 시점부터는 실행 여부를 확인하게 되며 같은 요청으로 다시 실행하지 않는다.
- 단일 대기 요청만 취소할 수 있다. 센트럴이 시작을 확인하기 전에 만료되면 새 요청을 낼 수 있다. 시작을 확인한 뒤 결과를 받지 못하면 결과 미확인으로 표시하며, 나중에 최종 결과를 접수할 수 있다.

지원되는 배포는 EL9/EL10 x86_64 관리형 RPM이다. 예외적으로 특정 호스트를 원격 제거에서 제외하려면 root 소유의 표준 YAML에 아래 값을 설정한다.

```yaml
central:
  remote_removal_enabled: false
```

패키지가 제거된 후 실행 중인 작업자는 중앙 응답을 받기 위해 잠시 재시도한다. 그 시간 동안 중앙에 연결할 수 없으면 결과가 로컬 작업 저널에 남고 콘솔에는 결과 미확인으로 표시된다. 패키지 제거 여부와 등록 상태를 별도로 확인할 수 있다.

## 검증 계획

- 프로토콜 서명 변조, 등록 교체, 만료, 다른 작업 챌린지와 요청 재사용을 확인한다.
- 관리자 확인과 CSRF, 호스트 허용, 제거 금지 정책, 업데이트 충돌, 대기 취소, 중복 보고, 최종 확인 전 인증서 유효 여부를 시험한다.
- 격리 환경에서 모의 RPM 실행으로 시작 ACK 선행, 고정된 패키지의 부재 확인, 실패 시 보존되는 상태를 확인한다. 실제 패키지 제거 시험에는 폐기 가능한 EL9/EL10 호스트가 필요하다.
