# 원격 에이전트 운영 설정

## 적용 계약

관리형 에이전트가 현재 등록의 mTLS 연결에서 별도 서명된 운영 설정을 받는다. 정책 서명 키를 사용하며 기존 보안 정책과 서명 문맥, 리비전, 적용 결과를 분리한다. 센트럴은 최신 적용 리비전과 등록 세대를 미리보기와 발행에 결합한다. 과거 리비전, 적용 기준 불일치, 만료, 서명 불일치에는 직전 승인값을 사용한다.

| 필드 | 중앙 지정값 | 상속 |
| --- | --- | --- |
| `monitoring.sample_interval_seconds` | 정수 5~3,600초 | 로컬 기본 10초 |
| `retention.observation_history_minutes` | 정수 60~1,440분. 호스트의 YAML 상한 이하 | 호스트 YAML의 분·일 단위 보존 |
| `local_panel.access` | `allow` 또는 `block` | 기존 호스트 패널 접근 |

필드별 첫 설정이나 상속을 적용할 때까지 기존 값을 사용한다. 자원 표본 주기를 처음 설정하거나 상속한 이후에는 하트비트를 10초마다 보내고, 별도 수집기가 표본 주기를 지킨다. 기존 자원 모니터링 켜기·끄기와 프로세스 목록 한도는 현행 보안 정책 값을 사용한다.

`agent_configuration.max_observation_history_minutes`의 제품 상한과 기본값은 1,440분이다. YAML에서 60~1,440으로 낮추거나 0으로 지정해 중앙 보존값 요청을 제한할 수 있다. 보존 기간이 줄어드는 요청에는 상속을 포함해 별도 확인이 필요하다. 이미 만료된 이력은 기간을 늘려도 돌아오지 않는다. 수집, 용량 보고, 축소 저장, SQLite 만료는 같은 실효 기간을 사용한다.

패널은 기존 Unix 소켓에서 접근값을 읽는다. 차단이면 요청을 403으로 거절하고 진행 중인 페이지·API 요청을 취소한다. 인증 쿠키를 패널 접근 결정 세대에 묶어 재허용 시 이전 쿠키를 무효화한다. 패널 실행·바인딩·인증은 호스트 설정이 담당한다. 게이트의 HTTP 동작은 테스트에서 확인하며 운영 하트비트의 패널 값은 에이전트가 승인한 결정이다.

## 중앙 API와 검증

- 에이전트는 `GET /v1/agent-configuration`을 폴링한다. 미할당과 이 경로를 지원하지 않는 센트럴은 기존 값으로 동작한다.
- 하트비트 capability `agent.configuration`의 `details.snapshot`에 실효값, 필드별 출처, 요청·적용 리비전과 결과를 보고한다.
- 센트럴의 정책 화면과 연결할 때 운영 설정 API의 미리보기·확인·상태 조회를 사용한다. 에이전트 화면 UI는 별도 작업이다.
- Agent 루트, Agent `protocol`, Central 루트를 임시 Go 작업공간에 등록해 로컬 검증한다. 독립 RPM 빌드 전에 공유 프로토콜 새 버전을 발행하고 두 모듈을 고정해야 한다.
