# 탐지·규칙 관리·무결성 실행 계획

**승인된 계획 · 2026-11-18**  
첫 개발 묶음은 **중앙 서명 정책(2), 규칙 제어·운영자 판정(3), TPM 없는 기본 무결성(5)** 으로 한다. 현장 검증(1)은 먼저 시작하고, 2의 정책 계약을 확정하면 3과 5를 병행한다. 1의 결과는 운영 확대 여부와 허용 부하를 결정한다. 번호는 [원본 로드맵](detection-and-integrity-roadmap.md)을 따른다.

## 2. 공유 정책 계약과 중앙 배포

1. **설정 우선순위를 고정한다.** 제안은 서명 정책에서 서비스 범위 필드를 생략하면 기존 호스트 YAML을 사용하고, 필드를 보내면 그 목록 전체를 적용하는 방식이다. 명시한 빈 목록은 모든 서비스의 파일·TCP 범위를 끄고, 다음 상위 리비전에서 필드를 생략하면 YAML로 복귀한다. 두 출처 모두 서명 정책의 활성 서비스 목록과 대조한다. 서비스 안에서 빈 TCP 목적지 목록은 해당 규칙을 끄며, 특정 CIDR의 빈 포트 목록은 그 CIDR의 모든 포트를 허용한다.
2. **공유 프로토콜부터 검증한다.** 기존 정책의 서명 바이트와 검증 fixture를 보존하고 생략·빈 목록·실제 값이 서명 왕복 후 구별되는지 확인한다. 중복 서비스, 잘못된 경로·CIDR·포트, 64 KiB 한도 초과는 발행·수신 단계에서 검사한다. 현재 에이전트는 공유 모듈 v0.3.1, 센트럴은 v0.3.0을 고정하고 있다. 호환 시험 후 양쪽이 검증한 새 프로토콜 버전을 고정한다. [정책 계약](../../protocol/managed/policy.go) · [기존 호환 시험](../../protocol/managed/compatibility_test.go)
3. **에이전트에 한 번만 적용한다.** 서명·대상 등록·리비전·설정 유효성을 확인한 뒤 저장하고, 서비스와 규칙 엔진을 같은 스냅샷으로 전환한다. 거절되면 직전 승인 정책으로 계속 탐지한다. 로컬 규칙 조회와 재시작 복원에도 같은 실효 정책을 사용한다. [현재 적용 경로](../../internal/agent/managed_policy.go) · [서비스 범위 검증](../../internal/config/service_observations.go)
4. **센트럴에서 대상과 결과를 확인한다.** 기존 정책 템플릿, 그룹 미리보기, 직접 할당 경로에 같은 지원 검사를 적용한다. 현재 등록의 최신 하트비트로 지원을 확인한 호스트에만 확장 필드를 발행한다. 혼합 그룹은 미지원·미확인 대상을 명시한 뒤 지원 대상만 선택해 재검토할 수 있게 한다. 구버전에는 기존 형식의 정책 배포·갱신이 계속 가능해야 한다.

**완료 기준**은 구·신 에이전트가 섞인 시험에서 호스트별 지원 여부, 원하는 리비전, 실제 적용 리비전, 거절 사유를 중앙에서 확인하는 것이다. 잘못된 서명·설정, 낮은 리비전, 재시작, 중앙 단절을 포함한다. 정책 적용 여부와 실제 센서 수신 여부는 별도로 표시한다.

**격리 검증 결과.** 공유 모듈 v0.4.0에서 기존 서명 fixture와 64 KiB 경계 시험을 통과했다. 신규 센트럴과 에이전트를 임시 DB·인증서로 기동해 직접 할당과 그룹 미리보기 배포를 번갈아 실행했다. 호스트 설정 상속 → 중앙 범위 적용 → 빈 목록 → 호스트 설정 복귀의 네 리비전에서 로컬 규칙과 중앙의 적용 리비전·범위 출처가 일치했다. 리비전마다 파일·TCP 표본 네 건을 보냈고, 총 16건의 중앙 판정이 기대값과 일치했다. 빈 목록에서는 네 건 모두 일반 관측으로 남았다. 기존 센트럴 바이너리와 새 에이전트 두 대의 전송·복구 시험도 통과했다.

**2026-11-18 운영 결과.** 센트럴이 서명된 EL9·EL10 RPM 35를 GitHub에서 반입해 검증했다. 같은 EL10 한 대에서 RPM 34 → 35 배포가 성공했고, 23:50:12 KST에 기동한 데몬의 설치·실행 버전과 새 수집을 확인했다. 23:51:46–23:53:06 KST의 80.3초 동안 중앙 ACK는 110 증가했다. 입력 드롭·파싱 오류·전송 손실은 0이고 마지막 전송 대기는 0건이었다. 하트비트에 서명 정책 지원 계약 1과 범위 출처 `local`이 보고됐다. 운영 센트럴은 이 검증 시점에 RPM 16·DB 스키마 3이었다. 운영 호스트의 중앙 서명 범위 전환은 서버 업그레이드 후 검증할 항목이다. [공개 릴리즈](https://github.com/mkjang2000/Xe-AntiShell/releases/tag/v0.1.0-r35)

## 3과 5. 정책 계약 확정 후 병행할 작업

| 항목 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| **3a. 규칙 ID 제어와 예외** | 기존 규칙 카탈로그의 ID를 사용한다. 서비스별 활성 상태, 예외 사유·UTC 만료 시각을 서명 정책에 담고 수집과 경보 판정을 분리한다. 서비스 귀속이 없는 관측에는 특정 서비스의 예외를 적용하지 않는다. | 같은 이벤트 유형에서 대상 규칙만 꺼지고 다른 서비스·규칙의 판정은 유지된다. 만료 직전·정각, 중앙 단절, 에이전트 재기동 후에도 예외가 제때 끝난다. |
| **3b. 운영자 판정** | 센트럴에 원본 경보를 참조하는 판정 이력을 추가한다. 기존 운영자 권한으로 정상·의심·판정 보류, 판정자·시각과 근거를 기록한다. 경보 발생 당시의 규칙과 정책 리비전을 보존한다. | 권한 없는 쓰기가 거절된다. 재전송으로 판정이 중복되지 않고 재분류 전후 기록을 조회할 수 있다. 일반 관측이 만료된 뒤에도 최초 경보 근거를 조회할 수 있다. |
| **5a. 승인 기준값** | 센트럴이 발행자 서명을 검증한 RPM에서 에이전트 바이너리 4개와 systemd 유닛 3개의 기대 SHA-256을 추출해 패키지 버전·아키텍처·RPM 다이제스트와 묶는다. 설치 후 보존되는 사이트 YAML과 규칙에는 운영자가 승인한 설정 다이제스트와 리비전을 연결한다. | 동일 릴리스에서 기준값이 재현된다. 기존 사이트 설정을 보존한 RPM 업그레이드, 미등록 기준, 승인된 설정 갱신을 구분한다. [릴리스 서명 계약](../../protocol/managed/releases.go) · [RPM 파일 목록](../../packaging/rpm/xe-antishell.spec) |
| **5b. 호스트 측정과 중앙 표시** | 이벤트 처리와 독립된 작업에서 지정 파일을 읽는다. 회차별 파일 수·읽기 바이트에 상한을 두고 다음 회차에 이어간다. 호스트는 측정값과 시각을 보내고 센트럴은 승인 기준과 비교한다. | 정상, 승인 업데이트 후 새 기준 일치, 예상 밖 변경, 누락·읽기 실패, 측정 기한 경과를 구분한다. 검사 도중 파일 교체·재시작을 시험하고 변경 없는 호스트에서 반복 비용을 1의 기준과 비교한다. TPM 없는 호스트에서도 결과가 표시된다. |

5의 결과는 에이전트가 보고한 파일 측정이다. 센트럴은 기본 파일 검증, IMA 측정 목록 접근, TPM 장치 접근, 원격 증명을 각각 표시하고 구현된 기능의 적용 상태만 갱신한다.

## 개발 묶음별 검증

- 에이전트·공유 프로토콜과 센트럴 각각의 `make verify`를 실행한다. 이어서 `XEAS_CENTRAL_TEST_BINARY`에 검증 대상 센트럴 바이너리를 지정하고 `TestIndependentCentralWithMultipleAgents`의 실제 실행을 확인한다. 호환 시험에는 구버전 에이전트와 기존 정책 서명 fixture도 포함한다.
- 60분 보존 설정에서 일반 관측 만료 후 경보 근거와 미전송 자료가 남는지, 단절 후 재전송·ACK가 중복 경보나 판정 소실을 일으키지 않는지 확인한다. [최소 관측 이력](minimal-observation-history.md)
- 각 묶음은 코드·격리 시험 결과와 현장 확인 결과를 따로 기록한다. 그룹 확대는 단일 호스트의 실효 정책·정상 업무 표본·비용을 확인한 뒤 진행한다.
