# Tetragon 구독 중단 복구

## 목적과 범위

선택된 실시간 Tetragon 자식이 종료되면 같은 설정으로 다시 구독하고, 운영자가 마지막 중단부터 새 구독의 증거 저장까지 걸린 구간을 확인할 수 있게 한다. `auto`에서 Tetragon을 선택한 경우에도 같은 경로를 사용한다. audit는 dispatcher가 입력을 소유하며 replay는 EOF에서 끝나는 유한 입력이다.

## 처리 흐름

하나의 수집 goroutine이 자식 종료를 기다린 뒤 1초부터 최대 30초까지 두 배씩 늘어나는 간격으로 재시도한다. 대기는 서비스 종료 시 취소된다. 같은 수집기 인스턴스를 사용해 원본 프레임·파싱 오류 카운터를 누적한다. 정상 프레임 전달로 현재 파싱 오류를 해제한다.

구독마다 에이전트 내부 세대 번호를 큐 항목에 붙인다. 중단 시 이전 세대의 센서 수신 증명을 폐기한다. 이미 큐에 들어온 이벤트는 기존 저장 경로로 처리하고, 첫 새 세대 이벤트에 도달하면 이전 PID 소유자 추정을 해제한다. 실행 식별자로 연결된 과거 계보는 보존한다. 복구 시각은 새 세대의 보존 대상 이벤트가 SQLite에 새 행으로 커밋된 시점에 기록한다. 중복 재전달이나 필터에서 제외된 이벤트는 공백을 닫지 않는다. 센서별 가용성 판정에는 해당 세대의 실제 수신 근거를 사용한다. 저장·유지보수·부팅 시 계보 확인 오류는 독립적으로 보고한다.

## 운영 상태와 호환성

`collector.tetragon`의 기존 capability `details`에 `last_disconnect_at`, `last_recovered_at`, `reconnect_attempts`를 담는다. 시각은 UTC RFC3339Nano이며 재시도 횟수는 데몬 시작 이후 누적한다. 최근 중단 한 건을 표시하고, 같은 중단에서 재시도가 반복되면 최초 중단 시각을 유지한다. 복구 시각은 서비스가 증거 저장을 다시 확인한 시점이므로 조용한 호스트나 보존 범위가 좁은 설정에서는 늦어질 수 있다. 숫자로 커널 이벤트 손실량을 추정하지 않는다. 기존 공유 모델과 서명 계약을 그대로 사용한다.

## 검증

임시 Tetragon 명령과 실제 에이전트·SQLite로 EOF, 실행 실패, 새 구독에서 저장한 이벤트, 이전 세대 근거 배제, 정상 종료를 확인한다. 반복 실패 시 대기 상한, 대기 도중의 취소, 단발 파싱 오류 뒤 정상 수신, CLI·로컬 패널에서 진행 중·복구 상태와 구버전 입력도 검증한다.

2026-11-18에 이 변경을 적용한 독립 작업본에서 `make verify`와 탐지 재생 20건이 통과했다. 전역 파일 감시를 쓰는 기존 hostmetrics 검사는 제한 환경에서 race 옵션으로 3회 통과했다. 새 정적 바이너리와 임시 Unix 소켓으로 실행한 점검에서는 같은 데몬의 CLI가 첫 이벤트 저장, 중단, 한 차례 재구독, 두 번째 이벤트 저장과 복구 시각을 순서대로 보고했다. 이 점검의 입력은 합성 Tetragon JSON이며 실제 운영 커널에서의 중단 시간과 이벤트 손실량은 측정하지 않았다.
