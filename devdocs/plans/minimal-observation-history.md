# 최소 관측 이력

탐지와 입력 검증은 수집 시의 정규화된 근거를 활용한다. 보존 단계에서는 원문 JSON, 인자, 작업 디렉터리, 중복된 조상 스냅샷을 제외한다. 호스트·서비스·프로세스 식별자, 관측 결과, 구조화된 탐지 근거, 규칙·위험 점수와 요인은 보존한다. 동일 이벤트 ID 충돌을 찾는 데 필요한 정규화 데이터의 SHA-256은 로컬에만 보존한다.

`limits.observation_history_minutes`를 설정하면 해당 기간을 지난 일반 관측과 참조되지 않는 프로세스 정보를 주기적으로 정리한다. RPM의 기본값은 60분이며 설정 파일을 유지하는 업그레이드에도 필드가 없으면 적용한다. 명시한 0은 기존 보존 정책과 완전한 관측 저장을 사용한다. 소스 빌드는 필드를 생략하면 기존 동작을 유지한다. 경보가 참조하는 이벤트·프로세스와 전송 대기열은 보호한다. SQLite가 삭제된 페이지를 후속 저장에 재사용할 수 있으며 기존 파일에서 운영체제 공간을 회수하려면 별도의 압축 작업이 필요하다.

중앙에 전송하는 새 묶음에도 동일한 간결한 관측을 사용한다. 기존 전송 대기열의 인코딩·전송 순번과 기존 데이터의 읽기 및 재수신 검증을 보존한다. 중앙 자체의 보존 정책은 별도 관리 대상이다.

검증은 전체 자료로 탐지한 결과의 보존, 형식과 기존 이벤트 호환, 중복 및 충돌, 관측 만료와 경보·미전송 자료 보호를 포함한다.

## RPM 32 및 센트럴 16 배포 결과

EL9·EL10 RPM에서 기존 YAML의 60분 기본값, 명시한 0·120분 설정, 61분 된 일반 관측의 만료를 시험했다. 센트럴 RPM 16은 수신 원본 다이제스트로 재전송 무결성을 확인하고, 최소 페이로드의 일반 관측을 수신 1시간 후 배치로 삭제한다. 기존 SQLite DB는 복구용 임시 사본을 확보한 뒤 증분 공간 회수 모드로 변환했다. 재기동과 운영 수신 검증을 마치고 이 사본을 삭제했다.

운영 센트럴에서 등록된 네 에이전트의 수신과 새 레코드의 최소 저장을 확인했다. 호스트별 최근 프로세스 실행 표본의 평균 페이로드는 변경 전보다 약 67~78% 작았다. 기존 이력의 만료 인덱싱은 완료됐으며, 실제 첫 만료 시점은 이번 배포 확인 이후다. 만료 동작과 증거 보호, 재전송은 별도 테스트에서 검증했다.

에이전트 세 대가 중앙 RPM 32 자동 설치 및 재시작 후 수집 검증을 통과했다. 각 에이전트의 70초 관찰 중 60분 최소 저장이 활성화됐고 입력 드롭·파싱 오류·중앙 전송 손실이 증가하지 않았다. 나머지 한 대에서는 SELinux가 업데이터의 `NoNewPrivileges=yes` 상태에서 RPM 설치 스크립트 도메인 전환을 거부했다. 로컬 관리자가 발행자 검증을 거친 RPM 32를 직접 설치한 뒤, 센트럴에서 네 대 모두의 RPM 32 실행과 60분 최소 저장을 확인했다. RPM 33은 정식 업데이터 유닛에 필요한 전환 설정을 담는다. [실패 원인과 복구](managed-agent-updates.md#selinux-rpm-scriptlet-transition)
