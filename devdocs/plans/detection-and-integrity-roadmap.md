# Xe-AntiShell 탐지·규칙 관리·무결성 개발 로드맵

2026-11-18 기준. 에이전트와 센트럴을 함께 다루며, 아래 번호는 권장 작업 순서다. **1번 현장 검증을 먼저 시작하고, 첫 개발 묶음은 2번 중앙 정책, 3번 규칙 관리, 5번 기본 무결성으로 잡는다.** 2번에서 서명 정책의 호환 방식을 정하면 3번과 5번은 병행할 수 있다.

착수 순서, 정책 우선순위와 단계별 완료 기준은 [실행 계획](detection-and-integrity-execution.md)에 정리했다.

## 출발점

- **파일·TCP** — 개발본에는 보호 경로 쓰기와 허용 목록 밖 TCP 연결 시작을 탐지하는 규칙이 있다. 격리 환경에서 두 에이전트의 경보가 센트럴까지 도달했다. 운영 RPM 32–33의 11월 18일 18:40 KST 하트비트에서는 네 대 중 한 대만 파일·TCP 센서 수신이 확인됐고 나머지 세 대는 `unverified`였다. 이 값은 개발본 배포 전의 수신 기록이다. [기능 보고서](../analysis/agent-capability-report.md) · [서비스별 규칙과 시험 결과](service-observation-rules.md)
- **정책·규칙** — 센트럴에는 그룹 정책과 서명 리비전 배포가 있고, 에이전트에는 규칙 목록과 로컬 정책 비교 기능이 있다. 서비스 이름은 서명 정책으로 받지만 보호 경로·쓰기 예외·허용 목적지는 호스트 YAML에서 읽는다. [서명 정책](../../protocol/managed/policy.go) · [서비스 설정 예제](../../configs/examples/agent-service-observations.yaml)
- **무결성** — 패키지 서명과 수신 데이터의 다이제스트 검증은 이미 동작한다. 패널의 ‘운영체제 파일 측정 정보’와 ‘TPM 장치 진단’은 각각 IMA 측정 목록과 TPM 장치의 가시성을 확인한다. 현재 센트럴의 무결성 설정은 적용 대기 상태이고, 호스트 파일의 일치 여부와 원격 증명 결과는 아직 산출하지 않는다. [기능 상태 판정](../../internal/agent/runtime_capabilities.go) · [무결성 설계](../../Linux_Host_Security_Platform_Design_v0.1.md)

## 1–4. 운영 검증과 규칙 관리

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | **파일·TCP 경보와 관리형 업데이트를 실서버에서 검증** | 수신 미확인 세 대에서 센서 적용 범위와 최근 수신을 확인하고, 확인되지 않은 호스트는 이유를 기록한다. 다음 패치를 SELinux Enforcing 호스트 한 대에 중앙 배포해 RPM 33에서의 자동 설치, 새 버전 기동, 수집 재개를 확인한다. 지정 서비스에서 보호 경로 쓰기와 목록 밖 TCP 시작은 중앙 경보로, 쓰기 예외와 허용 목적지는 일반 관측으로 처리되는지 확인한다. |
| 2 | **서비스별 파일·TCP 범위를 중앙 서명 정책으로 배포** | 그룹·서비스별 보호 경로, 쓰기 예외, 허용 CIDR·포트를 배포한다. 호스트 YAML과 중앙 값의 우선순위, 빈 목록과 설정 해제의 의미를 정한다. 센트럴에서 호스트별 지원 여부, 실제 적용 리비전, 거절 사유를 확인하고 구버전 에이전트에서 기존 정책이 계속 동작하는지 검증한다. |
| 3 | **규칙 ID 단위 제어와 운영자 판정 추가** | 서비스별로 개별 규칙을 켜고 끌 수 있고, 예외에는 사유와 만료 시각이 남는다. 만료 후 규칙이 다시 적용된다. 운영자는 경보를 정상·의심·판정 보류로 분류하고 당시 근거, 정책 리비전, 판정자를 조회할 수 있다. |
| 4 | **정책 영향 비교와 단계 배포 연결** | 같은 비식별 표본에 현행·후보 정책을 적용해 규칙별 경보 추가·감소·변경을 확인한다. 운영자가 한 대에 먼저 배포해 결과를 확인한 뒤 그룹으로 확대할 수 있다. 복구 시 이전 정책 내용을 더 높은 리비전으로 재발행하고 실제 적용까지 확인한다. |

## 5–8. 기본 무결성과 탐지 범위 확장

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 5 | **TPM 없이 에이전트 파일·설정 무결성 검증** | 검증된 배포 패키지에서 버전별 주요 파일의 기대 해시를 추출하고, 사이트 설정·규칙은 승인된 리비전에 연결한다. 정상 업데이트, 예상 밖 변경, 읽기 실패, 오래된 측정을 구분해 중앙에 표시한다. 검사 대상과 회차별 읽기량을 제한하고 변경이 없는 호스트의 반복 검사 비용을 측정한다. |
| 6 | **보호 파일 교체·삭제·권한 변경 탐지** | 현재 쓰기 훅만으로 놓치는 임시 파일의 이름 변경을 통한 원자적 교체부터 검증하고, 삭제와 권한 변경으로 확대한다. 보호 경로·쓰기 예외를 재사용하며 정상 패키지 배포, 로그 회전, 실패한 작업을 비교 표본에 포함한다. |
| 7 | **서비스·프로세스별 반복 TCP 연결 시도 집계** | 제한된 시간 안에 같은 서비스·프로세스가 같은 목적지·포트로 시도한 횟수, 최초·최근 시각, 관측된 결과를 요약한다. 재수신 시 중복 집계를 막고 목적지 종류가 급증해도 메모리 사용량을 제한한다. 현재 훅이 확인하는 연결 시작과 실제 연결 성립을 구별한다. |
| 8 | **파일·실행·권한·네트워크 이벤트 상관 탐지** | 보호 파일 변경 뒤 동일 경로가 실행되는 사례부터 구현하고 웹 출처 실행, 자격 증명 변경, 외부 접속으로 넓힌다. 호스트·부팅·프로세스 식별자와 시간 범위를 검증한다. 지연·역순·재전송에서도 경보가 중복되지 않고, 일반 관측 만료 후에도 생성된 경보의 최소 근거를 조회할 수 있어야 한다. |

## 9–12. 보고 신뢰도와 운영 연동

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 9 | **무결성 보고의 최신성 검증** | 5번의 측정에 센트럴이 발급한 일회용 값(nonce), 대상 호스트, 유효기간을 결합한다. 만료·재사용·호스트 불일치를 구분해 기록한다. 화면에는 행위 위험도와 무결성 신뢰 상태를 각각 표시해 정상 행위 점수가 측정 실패를 가리지 않게 한다. |
| 10 | **Linux IMA 파일 측정값 검증** | IMA 사용 호스트에서 선정한 측정 레코드를 부팅 단위로 증분 처리하고 승인 기준값과 비교한다. 재부팅·권한 부족·측정 정책의 범위 밖·기준값 불일치를 구분한다. 긴 측정 목록에서도 한 회차의 읽기량을 제한한다. |
| 11 | **수집 중단 경보와 외부 운영 연동** | 하트비트 중단, 평시 대비 수신 급감, 전송 적체·드롭, 인증서 만료 임박을 중앙에서 경보화한다. Syslog/TLS 수신처에서 시험 경보를 확인하고 인증서 자동 갱신과 센트럴 복구 훈련 후 기존 에이전트의 재연결·ACK 진행을 검증한다. 이 단계는 TPM 장비 없이 진행할 수 있다. |
| 12 | **지원 호스트에서 TPM 2.0·vTPM 원격 증명** | 신뢰할 수 있게 등록한 증명 키로 서명된 quote의 nonce와 PCR 측정값을 검증한다. 대상 장비에서 정상 부팅, 승인된 업데이트, 기대값 불일치, 오래된 응답을 구분한다. TPM 미지원 호스트에는 5번 기본 검증 결과를 계속 제공하고, vTPM 결과에는 하이퍼바이저 신뢰 조건을 명시한다. |

## 공통 검증 기준

- **부하** — 센서나 검사를 추가할 때 같은 입력·시간 구간에서 변경 전후 에이전트 CPU, 디스크 읽기·쓰기량, 이벤트 드롭, 전송 적체와 해소 시간을 비교한다. 파일 해시 검사, IMA 읽기, TCP 집계는 각각 처리량 또는 상태 크기에 상한을 둔다. 허용할 부하 증가는 1번에서 측정한 호스트별 기준을 바탕으로 정한다.
- **보존** — 일반 관측은 최소 정보로 1시간 보존하는 운영 정책을 유지한다. 새 규칙은 필요한 식별자와 판정 근거를 남긴다. 만료·재전송 시험에서 경보가 참조하는 증거와 전송 대기 자료가 유지되는지 확인한다. [최소 관측 이력](minimal-observation-history.md)
- **현장 판정** — 호스트의 지원 조건, 센서의 실제 수신, 규칙의 중앙 경보 도착을 각각 확인한다. 정책을 확대하기 전에 정상 업무 표본의 오탐과 수집 비용을 함께 검토한다. [에이전트 업데이트 검증](managed-agent-updates.md)
