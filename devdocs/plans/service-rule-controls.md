# 서비스별 규칙 제어와 임시 예외

정규화된 이벤트의 `process.origin_service`와 내장 규칙 ID를 정확하게 대조한다. 서비스 식별자가 없거나 마스킹·잘림·누락된 이벤트에는 서비스 제어를 적용하지 않는다. 대상 프로세스의 원본 귀속이나 호환되는 현재 PID의 cgroup을 확인한다. 부모 계보로만 보완한 서비스는 이벤트의 `missing_fields`에 `process.direct_service`를 남겨 내보낸 표본에도 예외가 적용되지 않게 한다. 이전 에이전트가 저장한 표본에는 이 구분이 없어 기존 `origin_service`의 귀속 근거를 사후 확인할 수 없다.

## 정책

`detection.service_rule_controls`는 서비스와 규칙의 조합별로 설정을 하나씩, 최대 256개 포함한다. 단독 모드는 로컬 YAML을 읽고 관리 모드는 현재 서명 리비전을 사용한다. 빈 배열과 필드 생략은 프로필 기본값을 사용한다. 발행 시 빈 배열은 생략해 기존 정책의 서명과 호환한다. 센트럴은 비어 있지 않은 배열을 보내기 전에 최신 등록의 `detection.service_rule_controls` 계약 1 지원을 확인한다.

| 모드 | 효과 |
| --- | --- |
| `enabled` | 프로필·입력·센서 조건을 충족한 규칙을 허용한다. |
| `disabled` | 해당 서비스에서 해당 규칙을 끈다. |
| `suppress_until` | `reason`과 UTC `expires_at`를 기록한다. 에이전트의 평가 시각이 만료 시각에 도달하면 그 시각부터 규칙을 허용한다. |

파일·TCP 범위, 웹 출처 조건, 전체 탐지와 권한 프로필은 계속 각각 적용한다. 관측 수집과 전송은 유지한다. 하나의 관측이 여러 규칙의 조건을 만족하면 활성 규칙 중 기존 우선순위에 따른 경보를 선택한다. 같은 원본을 다시 받으면 처음 저장한 경보 및 전송 묶음을 유지한다. SQLite 스키마 6의 전체 확정 원본(NULL)·압축 원본(SHA-256)은 보존한다. 빈 BLOB은 신규 미판정 원본에만 쓰고 최초 평가에서 확정하여, 관리 모드에서는 같은 트랜잭션에서 전송 묶음을 만든다. 원본 자체가 보존 기간을 지나 만료된 뒤 새 입력으로 제출하는 경우에는 현재 시점의 정책을 적용할 수 있다.

## 조회와 비교

`sentinel rules` 및 로컬 패널에서 규칙별 서비스 설정·사유·만료와 현재 예외 적용 여부를 확인한다. 오프라인 `sentinel rules compare --at 2030-01-01T00:00:00Z`는 두 설정과 모든 표본에 같은 평가 시각을 사용한다. 생략 시 비교 시작 시각을 결과에 기록한다. 이벤트에 포함된 과거 또는 미래의 시각은 예외를 연장하지 않는다.

## 검증

기존 서명 fixture, 신규 예외 변조, 미지원 혼합 그룹, 미리보기 후 지원 상태 변경, 미귀속·대소문자·다른 서비스·꺼진 프로필, 만료 직전과 정각, 서명 리비전 복원 및 중앙 단절, 같은 이벤트의 재전송과 고정 시각 비교를 시험한다.
