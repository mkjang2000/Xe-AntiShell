# 에이전트 파일 무결성 검사

## 승인과 표시

센트럴 관리자가 검증된 배포 RPM을 반입하면 센트럴은 내장 발행자 공개키, 서명된 패키지 크기와 SHA-256을 확인하고 같은 파일 디스크립터의 RPM 헤더에서 SHA-256 일곱 개를 추출한다. 대상은 패키지의 네 프로그램과 systemd 유닛 세 개다. 기존 카탈로그의 기준값은 처음 필요할 때 같은 절차로 채운다.

정책 템플릿에서 패키지 파일 검사를 선택하고 사이트에서 승인한 실제 sentineld YAML 바이트의 소문자 SHA-256을 입력한다. 비워 두면 설정은 기준 미등록으로 남는다. 템플릿을 그룹에 미리보고 배포하면 해당 등록과 리비전에 설정 해시가 고정된다. 규칙의 기대값은 중앙이 배포한 서명 정책 전체의 SHA-256이다. 에이전트는 로컬에서 검증해 적용한 정책 다이제스트, 등록 ID, 리비전, 만료 시각을 확인한 뒤 측정하며 저장된 정책은 원래 바이트 그대로 해시한다. 에이전트 버전 및 기존 heartbeat·정책 디코딩에는 선택적 별도 mTLS 엔드포인트를 사용한다.

## 측정 범위와 부하

- 센트럴은 YAML 내용이나 파일 경로를 요청할 수 없다. 호스트가 시작 시 선택한 YAML 경로와 고정 RPM 경로만 연다. 최종 심볼릭 링크 및 일반 파일 이외 타입은 읽기 실패로 기록한다.
- 파일 한 개는 64 MiB까지 측정한다. 회차당 최대 두 대상을 처리하며 4 MiB 읽기 예산을 다 쓰면 1초 후 이어서 처리한다. 파일 교체, 크기·mtime·ctime 변경은 별도로 표시한다. 읽는 동안 변경된 결과를 신뢰하지 않는다.
- 패키지 식별자가 있는 서비스가 시작 후 11초부터 등록·승인 여부를 1분 주기로 확인한다. 승인 변경 및 프로세스 재시작 시 새로 측정하며 완료한 검사는 1시간마다 갱신한다. 송신에 실패하면 동일 결과를 다시 보낸다. 결과 한 건은 8 KiB 아래이고 서버는 등록별 최신 결과를 저장한다.
- 센트럴은 대상마다 2시간이 지난 측정을 기한 경과로 표시한다. 보고서가 수신되어도 과거 측정 시각은 갱신되지 않는다. 최근 10분 이내의 패키지 인벤토리, 설치 버전, 실행 버전이 확인되어야 RPM과 비교한다. 해당 등록의 최근 정상 업데이트 완료와 모든 대상 일치를 함께 확인하면 승인 업데이트로 표시한다.
- 검사는 sentineld의 기존 서비스 권한으로 수행한다. 읽기 권한 실패는 대상별로 표시한다. 이 단계의 신뢰 근거는 관리형 mTLS 인증서와 에이전트 측정이며, 호스트 관리자에 대한 독립적인 TPM 증명과 nonce 기반 검증은 후속 단계에서 다룬다.

## 검증

공유 계약, 읽기 예산, 파일 교체 및 실패 상태, 리비전·다이제스트 불일치, 재전송, 센트럴의 최신성·업데이트 판정을 테스트한다. 변경 없는 파일의 반복 검사 비용은 에이전트에서 다음 명령으로 측정한다.

```sh
go test ./internal/integrity -run '^$' -bench . -benchmem
```

5 MiB 워밍 캐시 fixture 측정 예시는 3회 평균 약 16.7 ms, 314 MB/s다. 논리적으로 파일 전체를 다시 읽었으며 실제 디스크 읽기량과 현장 CPU 비용은 배포 호스트의 캐시 및 스토리지에 따라 달라진다. 센트럴에서 검증된 공개 RPM을 테스트할 때 XEAS_INTEGRITY_TEST_RPM에 .rpm 파일, XEAS_INTEGRITY_TEST_UNIT에 같은 릴리즈의 sentineld.service를 지정한다.
