# TCP 대기 서비스 인벤토리

## 목적과 범위

서버에서 실제로 TCP 연결을 대기하는 서비스를 에이전트가 주기적으로 수집한다. 운영자는 로컬 CLI에서 목록을 읽을 수 있고, 센트럴은 기존 하트비트에 실린 스냅샷을 저장할 수 있다. 센트럴 정책 화면의 서비스 선택과 정책 대상 범위는 후속 작업이다. 발견된 목록은 정책 적용 범위, 예외, 종료 권한을 바꾸지 않는다.

## 에이전트 수집

- 에이전트의 네트워크 네임스페이스에서 IPv4·IPv6 TCP `LISTEN` 소켓을 읽는다. 각 행은 포트, 주소 계열, 바인딩 범위를 보고한다. 바인딩 범위는 `wildcard`, `loopback`, `interface`다. 바인딩 주소 자체는 수집 결과에 남기지 않는다.
- 소켓을 가진 프로세스와 cgroup v2의 정확한 시스템 `.service` 소속을 확인한다. 공유 소켓의 소속이 모호하거나 PID 1만 대기하거나, 사용자 세션과 컨테이너처럼 직접 시스템 서비스 귀속을 확인하기 어려운 경우에는 서비스 이름을 비워 둔다.
- 주기는 1분이고 각 스캔의 시간 예산은 2초다. TCP 테이블과 PID·FD 탐색에도 별도 상한이 있다. 확인한 서비스와 포트 순으로 정렬한 최대 64개 항목을 보관한다. 실제 전송 한도에서 행이 더 줄어들 수 있다.
- TCP LISTEN은 방화벽을 통과한 외부 도달성, HTTP 처리 여부, 웹셸 탐지 증거를 판정하지 않는다. 별도 컨테이너 네트워크 네임스페이스와 UDP는 조사 범위 밖이다. PID, 파일 경로, 명령줄과 실제 바인딩 주소는 보고하지 않는다.

## 보고와 호환성

로컬 `sentinel service-inventory` 또는 `sentinel --json service-inventory`와 중앙 mTLS 하트비트가 같은 메모리 스냅샷을 사용한다. 중앙 기존 스키마에 이미 있는 다음 경로를 사용한다.

```text
heartbeat.status.capability_report.capabilities["inventory.listening_services"].details
```

- `contract`는 문자열 `"1"`이다.
- `state`는 `pending`, `complete`, `partial`, `unavailable`, `stale` 중 하나다. `partial`은 읽기 권한, 수집 시간·크기 또는 전송 한도 때문에 누락이 있을 수 있음을 뜻한다. `complete`인 표본에도 개별 미귀속 리스너가 있을 수 있다.
- `snapshot`은 `sampled_at` (UTC RFC 3339), `state`, `listeners`를 담은 JSON 문자열이다. 항목은 `port`, `family` (`ipv4` 또는 `ipv6`), `binding`, 확인 가능한 경우 `service`를 포함한다. 바깥 문자열 이스케이프를 포함해 8 KiB로 제한한다.
- 최초 수집 전에는 스냅샷이 없다. 3분을 지난 표본은 `details.state=stale`이며 마지막 내용과 표본 시각을 유지한다. 조회기는 `details.state`와 표본 시각, 현재 등록을 함께 확인해야 한다. 해당 capability가 없는 구형 에이전트는 미지원으로 표시할 수 있다.
- 리소스 모니터링을 끈 경우에도 서비스 인벤토리는 수집한다. SQLite에 시계열로 쌓지 않고 하트비트에는 최신 스냅샷을 사용한다. 이 관측 경로는 정책이 종료 판단에 사용할 수 있는 런타임 증거와 분리한다.

## 검증

- IPv4·IPv6 바인딩 분류, 같은 소켓의 복수 소유자, 미귀속, 권한 오류, 스캔·보고 상한을 시험한다.
- 로컬 CLI의 표 및 JSON과 시작 대기·부분·오래됨·수집 불가 상태를 검증한다.
- 변경 전 센트럴 RPM 23을 임시 디렉터리에서 실행한다. 시험 에이전트를 등록한 뒤 리소스 모니터링을 끄고도 현재 등록의 하트비트가 서비스 표본과 기존 정책 적용 보고를 함께 받는지 확인한다.
