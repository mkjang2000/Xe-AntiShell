# Tetragon v1.8.0 observation source review

Reviewed release: Cilium Tetragon `v1.8.0`, commit `a5a667837d4b1ecd9018797994bb4e39b98702e1`.
This review uses official source, synthetic tests and isolated inline/I/O validation. The isolated validation left existing service PIDs and policies unchanged; no arbitrary memory/code inspection was implemented.

## Inline options without collecting code

`matchCmdArgs` is an actual v1.8.0 selector. Index zero means the first argument after `argv[0]`. The cache contains the first 256 bytes of arguments, including separators; only complete cached arguments match, and indexes are limited to 0–31. At most five argument filters are ANDed inside one selector, and at most five selectors are ORed. It requires the large BPF program support check, normally available on kernel 5.3 or newer; a kernel version alone is insufficient. The helper does not force this feature on unsupported kernels. [Official selectors](https://github.com/cilium/tetragon/blob/v1.8.0/docs/content/en/docs/concepts/tracing-policy/selectors.md), [cache/selector implementation](https://github.com/cilium/tetragon/blob/v1.8.0/bpf/process/pfilter.h).

The generated policies recognize the fixed Python `-c`, Node `-e`/`--eval`/`-p`/`--print`, PHP `-r`, Perl `-e`/`-E`, and Ruby `-e` options at indexes **0–2**. Every earlier argument must be a complete switch from a conservative runtime-specific allowlist, with at most two preceding switches. Script names, `--`, options consuming another argument, and earlier inline-code options cannot pass that allowlist. Thus `python script.py -c value` does not become an inline-code observation. Three preceding switches are outside this policy's coverage even if the runtime accepts the invocation. An observed option does not prove valid syntax, the presence of an operand, or successful code execution. This generated-policy bound does not impose an index-2 limit on the independent bounded exact-argv/audit classifier.

The five-selector API limit is not the usable Equal-filter budget: v1.8.0's `string_maps_N` outer arrays each have **eight** slots. Every Equal argument filter allocates one inner map in each used string-length bucket. Five alternative option positions need `1+2+3+4+5=15` short-string maps and fail at outer key 8 (`string_maps_0_8`), reported by the BPF library as “key too big for map.” Three positions need six maps and stay within that external capacity. Preserve exact Equal comparisons; replacing them with broad Prefix comparisons would change the evidence semantics. [Outer map definition](https://github.com/cilium/tetragon/blob/v1.8.0/bpf/process/string_maps.h), [map allocation](https://github.com/cilium/tetragon/blob/v1.8.0/pkg/selectors/selectors.go), [map population](https://github.com/cilium/tetragon/blob/v1.8.0/pkg/sensors/tracing/selectors.go).

The selector does not attach a matching-option boolean to a base `process_exec` event. Each option therefore has a separate fixed policy name and produces the independent `process.exec_observation` type. It contains only runtime, inline mode, policy evidence, and the option name. No matching code argument, memory bytes, environment, flattened argv, or hash of those values enters the normalized event.

### Hook ordering and its boundary

An `execve` entry kprobe is unsuitable: it sees the old process arguments. The generated policy instead uses **`raw: true`** on `sched/sched_process_exec`. Tetragon's base sensor also uses this raw tracepoint and is loaded before static/gRPC policies. Its exec hook updates the new process key, binary and argument snapshot synchronously before emitting its base event. [Base sensor](https://github.com/cilium/tetragon/blob/v1.8.0/pkg/sensors/base/base.go), [startup order](https://github.com/cilium/tetragon/blob/v1.8.0/cmd/tetragon/main.go), [exec map update](https://github.com/cilium/tetragon/blob/v1.8.0/bpf/process/bpf_execve_event.h).

Linux v6.6 raw BPF tracepoint registration uses the default tracepoint priority. Equal-priority callbacks are appended and executed in registration order. This gives source evidence for base-before-policy evaluation on that normal path; it is an inference from the two implementations, not a blanket guarantee for every vendor kernel. A non-raw perf tracepoint may have an earlier shared registration and cannot inherit that argument. [BPF registration](https://github.com/torvalds/linux/blob/v6.6/kernel/trace/bpf_trace.c), [callback ordering](https://github.com/torvalds/linux/blob/v6.6/kernel/tracepoint.c).

The installer only accepts its exact unit, rejects merged config and `TETRAGON_*` manager settings, and uses the default disabled cgroup-rate limiter. Enabling a cgroup-rate filter could skip the base cache update and invalidates this premise. After adding policies, the helper runs positives with zero, one and two approved preceding switches, plus script-before-option and three-switch beyond-bound negatives for each installed runtime/option. A positive policy event must agree with the base exec event's PID and opaque exec ID. Both negatives require a base exec receipt without that policy claim. Missing cache/unsupported attach/no actual receipt fails verification. Runtime capability remains unverified until the agent receives an accepted typed observation; a manifest alone cannot promote it.

## JSON envelope and strict normalization

The v1.8 protobuf envelope uses `process_exec`, `process_exit`, `process_kprobe` and `process_tracepoint`; `time` is the source event timestamp. Protojson uses snake_case. A process carries numeric host PID, opaque `exec_id`, `start_time` and binary. New observations require these identity fields rather than creating an identity from missing data. Parent/ancestor context uses the existing collector's boot-scoped identity normalization and local ingestion timestamps. [Event oneof](https://github.com/cilium/tetragon/blob/v1.8.0/api/v1/tetragon/events.proto), [typed payloads](https://github.com/cilium/tetragon/blob/v1.8.0/api/v1/tetragon/tetragon.proto), [encoder](https://github.com/cilium/tetragon/blob/v1.8.0/pkg/encoder/encoder.go).

Only the fixed owned names and exact corresponding hook/function are accepted. Action must be Post; enforcement actions and extra argument/data buffers are rejected. File and network payloads are allowlisted typed metadata. The source ID hashes exec ID, policy, source time and these safe facts. Local retry time and private source arguments do not affect identity. Raw event storage remains disabled for these new event types even if the general raw-storage configuration is enabled.

`long_arg` is protobuf int64 and can be a decimal JSON string; `int_arg` is int32. The parser supports bounded decimal strings/numbers and rejects overflow, floating point and an unexpected return union. Missing return values remain explicitly unknown.

## Actual file/network semantics

| Observation | Hook and input | Return interpretation | Coverage boundary |
| --- | --- | --- | --- |
| `file.write` | `vfs_write`, arg0 `file` only | positive: written byte count; zero: no data; negative: failed; absent: unknown | regular files in configured path prefixes; does not cover all writev, mmap, io_uring or durability |
| `network.connect` | `tcp_v4_connect` / `tcp_v6_connect`, **input arg1 `sockaddr`** | zero: initiated; negative: failed; absent: unknown | TCP connect invocation; zero does not mean established connection, packet delivery or successful application traffic |

Entry-time `sock_arg.daddr` can still be uninitialized inside a connect function, so the policy captures the input sockaddr rather than that socket field. `returnCopy` is not a general socket reread facility. The typed sockaddr becomes `family`, `addr`, `port`; the parser verifies IPv4/IPv6 family and hook agreement with `netip.ParseAddr`. [Argument conversion](https://github.com/cilium/tetragon/blob/v1.8.0/pkg/grpc/tracing/tracing.go), [argument schema](https://github.com/cilium/tetragon/blob/v1.8.0/pkg/k8s/apis/cilium.io/v1alpha1/types.go).

`security_file_permission(MAY_WRITE)` would report authorization rather than an actual write, and is intentionally not used. There is no policy here for arbitrary JVM, .NET, PHP worker or interpreter memory. Long-lived worker file/network side effects are observable only when they invoke one of the supported hooks and satisfy policy scope.

## Scope, load and rollback

`python3 packaging/tetragon/observations.py` only prints usage. An operator must explicitly use `--apply`. This command requires the existing installer-owned, active v1.8.0 Tetragon and active agent. It prints the planned file prefixes and address families before mutation. It never starts or changes a foreign Tetragon instance.

File defaults are `/tmp/`, `/var/tmp/`, `/dev/shm/`, `/var/www/`, `/srv/`. Repeated `--file-prefix /absolute/directory/` options explicitly replace this set; `/tmp/` remains required for the private one-byte verification probe. Root `/`, traversal, control characters and unbounded lists are rejected. File/network policies also restrict current binary names to recognized web workers, supported interpreters, Java/.NET, shells and known I/O tools (`curl`, `wget`, `nc`, `ncat`, `netcat`, `socat`). Trusted installed canonical numeric runtime/`php-fpm` names and alternatives targets are discovered and persisted as policy inputs. Renamed/custom binaries are outside initial scope. No sampling/rate limiter is configured; this finite scope still has workload-dependent overhead and does not claim complete host I/O coverage. The agent separately enforces web-origin retention.

Generated YAML files live in `/opt/xe-antishell/tetragon/policies`. Every regular file in that directory is parsed by upstream startup, regardless of suffix, so the ownership manifest is stored outside it at `/opt/xe-antishell/tetragon/observations.json` with root 0600 permissions. No upstream install script is executed. [Static loader](https://github.com/cilium/tetragon/blob/v1.8.0/cmd/tetragon/main.go).

Runtime changes use the existing Unix-socket API with explicit `--domain static`, and static files restore them after restart. The helper checks all domains for same-name foreign policies, rejects conflicting ownership/files before mutation, and requires every owned policy's state enabled, no policy error, and mode `TP_MODE_MONITOR_ONLY`. Kprobes must additionally report nonempty per-hook status with every hook loaded. v1.8.0's generic tracepoint sensor leaves `Sensor.Statuses` empty, so only the nine fixed inline names may omit that list; matching positive/negative actual probes still remain mandatory. Missing hook status for arbitrary names or file/network kprobes is rejected. If only IPv6 attachment is unavailable, it retries the newly owned network policy with IPv4 only. Unrelated policies are neither deleted nor changed. [CLI](https://github.com/cilium/tetragon/blob/v1.8.0/cmd/tetra/tracingpolicy/tracingpolicy.go), [tracepoint sensor](https://github.com/cilium/tetragon/blob/v1.8.0/pkg/sensors/tracing/generictracepoint.go), [policy mode](https://github.com/cilium/tetragon/blob/v1.8.0/pkg/sensors/tracing/policyhandler_linux.go), [status schema](https://github.com/cilium/tetragon/blob/v1.8.0/api/v1/tetragon/sensors.proto).

The shared exclusive installer lock covers preflight, backup, API mutation and verification. Root-only diagnostic backups precede switching. On backup, attachment, agent restart, stream, probe, or SIGINT/SIGTERM/SIGHUP failure, newly attempted static policies are removed and previous files/configuration/agent operation restored; rollback attempts independent parts even after one failure. Tetragon's existing base process is not restarted. Repeating a verified installation preserves agent configuration values and avoids unnecessary restarts or API adds.

The agent gRPC subscription excludes `arguments` and `environment_variables` under process/parent/ancestors on the server. Existing detection, response, privacy, filters, identities and database paths are retained. The base installer preserves that exact exclusion subscription on later runs. Probe receipt rejects any nonempty excluded private field. Process bytes remain transient inside Tetragon's own argument selector cache; this feature does not erase that upstream internal cache.

After actual probes, manifest schema 1 records pinned version, exact generated file hashes, scope, canonical runtime suffixes, requested network families, verification time, `verified_runtime_policies` and `verified_network_families`. Uninstalled runtimes and unavailable IPv6 are listed as unverified rather than simulated. Positive file proof uses a private `/tmp` file and one-byte write; TCP proof uses a private loopback listener. No external network destination is contacted. The manifest is installation evidence and is not a substitute for the agent's own fresh runtime receipts.

## Validation boundary

Collector tests use official-shaped synthetic envelopes: all nine inline policies; independent event identity; source/local clock separation; retries; raw-argument deletion; invalid identities/hooks/actions; file path/return boundaries; IPv4/IPv6 sockaddr/return validation. Packaging tests use temporary files, identity adapters and mocked service/policy APIs, including partial-attach rollback, retry, foreign ownership, marker mismatch, no-argument behavior and IPv4 fallback.

Isolated monitor-only validation passed on EL9 kernel `5.14.0-687.66.1.el9_8.x86_64`: all eleven policies reported enabled monitor-only status. Eight installed option policies (Python `-c`, Node `-e`/`--eval`/`-p`/`--print`, PHP `-r`, Perl `-e`/`-E`) passed positive probes at indexes 0–2 plus script-before-option and beyond-bound negative probes. Ruby was not installed. A private one-byte write returned 1, and loopback IPv4/IPv6 connect calls returned 0 with matching source process identity. The transient instance used a private runtime mount, unique BPF pin directory, bounded memory/time and server-side argv/environment exclusions. All five baseline service PIDs stayed unchanged and transient pins were removed. Event bodies were neither printed nor written to disk. Python 3.9 regressions cover nanosecond protobuf timestamps and numeric socket-family transport; benign probe child failures now fail explicitly and always clean up. This verifies those particular sensor/probe paths, not the separate agent-receipt gate, retained history, central delivery, complete I/O coverage, TCP completion, other target kernels or sustained workload overhead.
